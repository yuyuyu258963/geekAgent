# geekAgents


用 TypeScript/Node.js 动手实现一个最简单的 Agent/Harness，从零实现 REPL 循环与流式多轮对话。
- R：read 捕获并解析输入
- E：执行并更新状态
- P：序列化并展示结果
- L：尾递归/事件复盘

# Day1：一个最简单的 Agent 的 REPL 地基

## REPL 是什么

REPL 是 Read-Eval-Print-Loop 四个词的缩写，翻译过来就是 【读入 -> 求值 -> 打印 -> 再循环】。这个模式实际上就类似于常用的命令行、Python 交互式解释器、node 不带文件名直接敲，全都是 REPL：打一行、回一句、光标又亮起等下一行

为什么 Agent 的地基要选 REPL？因为人和模型对话的本质就是【一来一回循环】：我们输入、模型答、再输入... 一个会反复收集输入的循环，恰好就是 REPL 的本意。所以第一阶段就是先把这部分能反复聊的循环跑通，后面加工具、加文件读写，都是在循环中塞新的东西

## 为什么不直接用 curl

可能会想：调模型不就是发个 HTTP 请求嘛？curl 一行搞定，为什么还需要写多余的代码
Day1 REPL 的好处有：
- 连续对话：输入后自动进入下一轮
- 多轮记忆：history 自动累积并重发
- 流式输出：收到一个片段就打印一个
- 信息区分：用户、模型、系统分别着色

# Day2 工具调用循环
Day2 实现工具调用循环：模型可以请求 get_current_time, 程序执行后把真实时间返回模型，为后续命令与文件工具打下基础

## 设计：先约定工具、消息和结果
1. 工具 = 一个对象。名字 + 描述 + 参数 JSON Schema + 一个 run 函数。模型只会看到清单声明的工具，run 才是真实世界
2. history 依然是那个数组。工具调用只是一种新的 message 角色：assistant 发起 tool_calls，以及回传的 tool 消息
3.  结果只有字符串。工具 run 的结果一律转成字符串回传给模型。真实世界（时间、命令输出、文件内容）最后都折叠成一行文本，模型层面不需要任何结构化协议
